# Site Survey Dashboard

Web app to store, search, sort and manage every Elevator RF Survey report
generated by the [Elevator-assesment-app](https://github.com/roboticstsl-ops/Elevator-assesment-app)
phone app, in one place.

## Decided so far
- **Backend: Supabase** (Postgres + Auth + Storage) — not Mongo. The data is
  fixed-shape (one row per survey, JSONB columns for fields/checklist/rails/rf),
  and the dashboard is table + filters + search, which is what SQL is for.
  Supabase also gives auth and file storage for free instead of hand-rolling both.
- **Phone app stays offline-first.** No live sync. A "Submit to server" step
  gets added alongside the existing Export / Send-to-Telegram buttons — it
  pushes the finished survey to Supabase when you have signal, same as the
  Telegram delivery does now. Filling the form on site never depends on a
  connection.
- **Photos** move from base64-in-JSON (how the phone app stores them locally)
  to Supabase Storage URLs once submitted.
- **One row per survey**, columns roughly: id, created_at, prepared_by,
  site_name, client, elevator_id, floors, feasibility, status, fields (jsonb),
  checklist (jsonb), rails (jsonb), rf (jsonb), photos (jsonb array of storage
  paths), docx_path (storage path to the generated report).

## Scope (v1, from the mockup)
- Surveys list: stat tiles (total / feasible / need attention / not feasible),
  search + filter (status, client, date range), sortable table, pagination.
- Survey detail: tabs — Summary, RF Results, Railing Measurements, Photos,
  Documents. Download the stored .docx. View full report.
- Auth (who logs in — Users page in the mockup).
- Map view (site locations) — later, not v1 blocking.

## Not decided yet — first things to settle when we start
- Framework for the dashboard (kept the phone app plain HTML/JS on purpose;
  open whether the dashboard does the same or uses something like React —
  more UI state here, worth discussing).
- Exact Supabase schema + RLS policies.
- How "Submit to server" auths from the phone app (anonymous project key vs.
  per-user login on the phone too).
- Whether the dashboard can also *regenerate* the .docx from stored JSON
  (reusing docxData()/template.docx from the phone app) or only ever stores
  what the phone app already exported.
